# GazeDot — 안드로이드 시선 추정 시제품

전면 카메라에서 눈·홍채 위치를 검출하고 **사용자별 9점 보정**을 거쳐 화면의 추정 시선 위치에 빨간 점을 표시합니다. 홈 화면이나 다른 앱으로 이동한 뒤에도 카메라 포그라운드 서비스와 터치가 통과하는 오버레이가 동작합니다.

## 현재 상태

Android Studio에서 저장소 루트 폴더를 열 수 있습니다. APK는 로컬에서 빌드하며 빌드 산출물은 저장소에 포함하지 않습니다.

첫 실기기 사용에서 좌우 시선 이동이 잘 반영되지 않는 문제가 보고되었습니다. 보정값 저장·재사용, 머리 각도·거리 변화 보완은 아직 구현하지 않았습니다. 현재 버전은 매번 시작할 때 9점 보정이 필요한 실험용 시제품입니다.

## NoTouch 작성 기능 준비 상태

지원 앱의 메시지 입력칸을 선택하면 **NoTouch로 작성** 버튼이 나타납니다. 버튼을 직접 선택한 뒤 작성 방식을 고릅니다. 검색창·비밀번호·확인되지 않은 앱/입력칸은 제외합니다. 앱별 어댑터는 카카오톡, 삼성 메시지, 갤럭시에서 사용하는 Google 메시지의 알려진 입력칸 ID만 허용하며, 대화 제목 메타데이터나 선택 위치를 확인할 수 없으면 표시하지 않습니다. 각 앱 버전에서 실제 입력 연결은 별도 실기기 검증이 필요합니다.

- **자주 쓰는 문장 선택**: 지정된 기본 문장 6개를 2열×3행으로 제공합니다. ‘문장 바꾸기’에서 카드·카테고리·준비된 문장/직접 작성을 선택하고 저장합니다. 취소하면 기존 문장과 순서를 유지합니다. 개인화는 처음부터 강제하지 않습니다.
- **직접 입력하기**: 자모 그룹 없이 자모 버튼을 바로 표시합니다. 한글 조합·지우기·띄어쓰기·실행 취소를 제공하며, 긴 목록은 ‘위로 보기/아래로 보기’로 이동합니다. 온라인 예측 없이도 사용할 수 있습니다.
- **외부 반영**: 기본 문장은 선택 시 한 번 추가합니다. 직접 입력은 NoTouch 초안에서 조합·삭제·후보 선택·실행 취소한 뒤 **입력칸에 추가**를 눌러 반영합니다. 선택된 기존 텍스트는 유지하고 선택 영역 끝에 추가합니다. 메시지 전송·Enter·받아쓰기를 실행하지 않습니다.
- **대상 확인**: 패키지·창·노드·대화 제목 메타데이터·원문·커서를 다시 확인한 뒤 반영하고, 실제 텍스트와 커서를 읽어 결과를 확인합니다. 외부 화면 내용이 바뀌면 보수적으로 연결을 중단합니다(새 메시지 수신도 해당할 수 있음). 제목이 같은 대화방의 노드 재사용에 대비해 외부 내용 변경 이벤트도 연결을 무효화합니다. 앱 업데이트에 따른 식별 실패는 자동 추정으로 우회하지 않습니다.
- **초안 보존과 종료**: 모든 작성 화면 상단에 ‘NoTouch 작성 끄기’가 있습니다. 미반영/반영 불확실 초안은 앱 내부에 보관하고, 다시 진입할 때 확인 후 이어 씁니다. 결과가 불확실하면 자동 재삽입하지 않습니다. 기기 저장 실패는 메모리 보관 상태로 안내합니다. 편집 중인 문장과 외부 메시지 입력은 분리합니다.
- **시선 선택**: 기존 유효한 연속 1초 응시를 사용하며, 무효·중단·이탈 시 타이머를 초기화합니다. 화면 전환 후 버튼 밖을 바라본 뒤 새로 응시해야 합니다. 작성 중에는 뒤쪽 앱의 시선 클릭·스크롤·받아쓰기를 차단합니다. 같은 버튼에 머무르면 반복 선택되지 않습니다.

기본 문장은 [Tobii Dynavox QuickPhrases 안내](https://www.tobiidynavox.com/blogs/support-articles/navbar-pageset-adding-messages-to-quickphrases)를 참고한 초기 구성안이며 한국어 사용 빈도 상위 6개라는 뜻은 아닙니다. ‘도와주세요.’는 문구 삽입이며 긴급 신고나 자동 연락 기능이 아닙니다.

**AI 제공자·모델은 미정이며 API 키를 입력하지 않았습니다.** 설정 위치는 다음과 같습니다.

- `server/.env`: 나중에 실제 값을 채울 로컬 설정 파일입니다. Git에서 제외합니다.
- `server/.env.example`: 비밀키 없이 공유하는 설정 예제입니다. 새 환경에서는 이 파일을 `server/.env`로 복사해 사용합니다.
- `AI_PROVIDER`, `AI_MODEL`, `AI_API_KEY`, `AI_API_BASE_URL`, `AI_REASONING_EFFORT`: 제공자·모델 결정 후 채울 항목입니다. 미정·미입력 주석을 유지합니다. 현재 서버에는 OpenAI Responses 어댑터가 있으며 다른 제공자는 어댑터를 추가해야 합니다.
- `AI_PREDICTION_ENABLED=false`: 온라인 예측을 기본으로 비활성화합니다. 필수 설정이 비어 있어도 제공자 요청을 실행하지 않습니다.
- `online-prediction.properties.example` → `online-prediction.properties`: Android 빌드에 넣을 **HTTPS 중계 서버 주소만** 설정합니다. 앱에는 제공자 키나 모델을 넣지 않습니다. 주소가 비어 있으면 앱의 온라인 요청도 없습니다.

서버 실행·정책·요청 제한·테스트 방법은 [server/README.md](server/README.md)에 있습니다. 최초 온라인 사용 전에 제공자·모델·전송 데이터·보관 정책을 안내하고 선택하게 합니다. 단어 후보는 최대 2개, 이어쓰기 후보는 최대 1개이며 입력 버전과 적용 범위를 검증합니다. 응시·터치 중에는 후보 변경을 보류합니다. 한국어 미완성 자모의 실제 모델 품질은 모델 확정 후 별도 평가해야 합니다.

## 설치와 사용

1. `app/build/outputs/apk/debug/app-debug.apk`를 안드로이드 기기로 옮겨 설치합니다. Android 8.0/API 26 이상, 전면 카메라가 필요합니다. USB 연결 시 `adb install -r app/build/outputs/apk/debug/app-debug.apk`를 사용할 수 있습니다.
2. GazeDot에서 **권한 허용 및 카메라 시작**을 누릅니다. ‘다른 앱 위에 표시’, 카메라, 알림 권한을 허용합니다. 오버레이 설정 화면에서 앱으로 돌아옵니다.
3. 기기를 고정하고 얼굴을 정면에 둡니다. **눈 검출됨** 상태가 되면 **9점 시선 보정**을 누릅니다.
4. 머리는 움직이지 않고 파란 점을 눈으로 따라갑니다. 점마다 약 2.5초 이상, 유효 표본 22개를 모읍니다. 보정은 약 25~40초가 걸릴 수 있습니다.
5. 보정 후 빨간 점을 확인하고 **홈 화면에서 빨간 점 확인**을 누릅니다. 설정 앱 등 일부 화면에서는 안드로이드 보안 정책에 의해 오버레이가 숨겨질 수 있습니다.
6. 앱의 **추적 중지** 또는 알림의 **중지**를 누르면 카메라와 오버레이가 종료됩니다.

앱을 처음 실행했을 때 카메라 권한을 거부했다면 다시 허용해야 합니다. 영구 거부한 경우 시스템 앱 설정에서 허용합니다. 화면 꺼짐, 회전, 화면 크기 변경 시 서비스를 종료하며 앱에서 다시 시작·보정합니다. 시스템에 의해 앱 프로세스가 종료된 경우에도 자동으로 카메라를 켜지 않습니다.

## background process인가?

일상적인 의미로는 앱 화면을 떠난 뒤에도 동작하는 백그라운드 기능이지만, Android 구현은 **camera 유형 Foreground Service**입니다. 앱 화면이 보일 때 사용자가 시작하고, 지속 알림을 표시하면서 카메라를 유지합니다. 빨간 점은 `TYPE_APPLICATION_OVERLAY` 창입니다. 접근성 서비스나 화면 캡처 권한은 사용하지 않습니다. 다른 앱을 클릭하는 기능은 포함하지 않습니다.

## 실제 구현과 한계

- CameraX ImageAnalysis: 전면 카메라, RGBA 프레임, 센서 회전 보정, 최신 프레임만 처리, 추론 최대 약 15fps.
- MediaPipe Face Landmarker: CPU에서 얼굴·눈·홍채 랜드마크 478개 검출.
- 양쪽 눈의 모서리 축을 기준으로 홍채의 상대 수평/수직 변위를 계산. 눈이 감기거나 랜드마크가 없으면 점을 숨김.
- 9개 목표의 표본 중앙값으로 정규화된 ridge 선형 회귀를 학습해 화면 좌표로 변환.
- 보정 시 시선 변화가 너무 작거나 적합 오차가 크면 실패 처리. 얼굴 위치·거리 변화가 큰 경우 점을 숨김. 미세한 고개 회전까지 완전히 보정하는 모델은 아님.
- 화면 좌표에 지수 평활화 적용. 800ms 넘게 결과가 없으면 점을 숨김.
- 전체 화면 오버레이는 터치를 받지 않고 창 불투명도를 0.7로 설정해 Android의 터치 통과 조건을 고려함.

**홍채 검출 모델 자체가 화면 시선 좌표를 출력하는 것은 아닙니다.** 이 앱은 개인 보정 기반의 초기 시선 추정 실험입니다. 작은 버튼을 정확하게 선택할 수 있다는 보장이 없으며 기기, 조명, 안경, 눈 형태, 머리 위치에 영향을 받습니다. 보정 데이터의 적합 오차는 실제 사용 정확도가 아닙니다. 별도의 목표점 검증이 필요합니다.

카메라를 사용하는 다른 앱과 동시에 전면 카메라를 공유하지 못할 수 있습니다. 제조사의 배터리 관리, 카메라 정책, 분할 화면·폴더블 화면 전환에 따라 실기기 확인이 필요합니다.

## 개인정보·네트워크

영상은 기기 내 메모리에서 처리하고 프레임 처리 후 해제합니다. 영상·얼굴·시선 데이터는 예측 서버로 보내지 않습니다. 개인화 문장·초안·온라인 동의는 앱 내부 SharedPreferences에 저장하며 백업에서 제외합니다. 대화 내역은 수집하지 않고, 외부 연결 확인에는 입력칸 내용과 알려진 대화 제목 메타데이터만 기기 내에서 사용합니다. 보정값은 세션 메모리에만 있으며 서비스가 종료되면 제거됩니다.

INTERNET 권한은 선택적인 온라인 예측용입니다. 기본 설정에서는 서버 주소·제공자·모델·키가 비어 있고 온라인 예측이 꺼져 있어 요청하지 않습니다. 사용자가 동의한 뒤 작성 중인 NoTouch 초안만 HTTPS 중계 서버에 전송합니다. 서버는 본문·후보를 저장하거나 로그로 남기지 않습니다. 제공자 데이터 보관 정책은 동의 안내에서 별도로 확인합니다. 기존 시스템 받아쓰기의 데이터 처리는 해당 음성 인식 제공자 정책을 따릅니다.

## 빌드

Android Studio에서 이 폴더를 열고 SDK 35를 설치합니다. JDK 17 또는 21을 사용합니다. `local.properties`의 `sdk.dir`는 각 PC의 SDK 경로를 사용합니다(버전 관리 제외).

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Gradle 8.13 / AGP 8.9.2 / Kotlin 2.1.20 / CameraX 1.4.2 / MediaPipe Tasks Vision 0.10.26을 고정해 사용합니다. 첫 빌드에는 라이브러리 다운로드를 위한 인터넷이 필요합니다. 기본 문장·직접 입력·기기 내 시선 추적은 오프라인에서 사용하며, 선택적인 온라인 예측에만 서버 연결이 필요합니다.

## 실기기 확인 항목

- 보정 후 보정에 쓰지 않은 화면 위치를 바라보며 오차·반응 지연을 측정.
- 머리를 고정한 상태에서 눈만 좌우·상하로 이동했을 때 점이 따라오는지 확인.
- 홈/브라우저로 전환하고 2분 동안 점·알림·터치 통과 확인.
- 눈 감기/얼굴 가리기 시 점 숨김, 복귀 시 추적 재개 확인.
- 회전/화면 끄기/중지 버튼 후 카메라 표시와 점이 사라지는지 확인.
- 오버레이/카메라 권한 거부 및 취소, 다른 카메라 앱 실행 시 확인.

## 파일 안내

- `MainActivity.kt`: 권한, 상태 화면, 9점 보정 UI.
- `TrackingService.kt`: 카메라 포그라운드 서비스, 추론, 생명주기·종료.
- `LandmarkFeatures.kt`: 홍채의 눈 내부 상대좌표 추출.
- `GazeMath.kt`: 보정 회귀, 품질·얼굴 위치 검사.
- `DotOverlay.kt`: 다른 앱 위의 빨간 점.
- `GazeMathTest.kt`: 미관측 좌표 예측, 무효 보정·얼굴 이동·이상값 검사.
