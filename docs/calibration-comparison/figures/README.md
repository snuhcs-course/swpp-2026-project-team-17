Every recording gets its own folder, `<collection>/<PARTICIPANT>_<LABEL>_<short session ID>/`, so it cannot overwrite
another. The tool also refuses to rewrite an existing session folder with different figures unless `--replace` is given.

## Summary view: two figures per session

Each session's three head-position blocks (NEUTRAL, HIGHER, LOWER) and two passes are combined per target, so each of
the 16 targets has six presentations. Sessions and participants are never combined. Presentations are matched to
targets by their grid coordinates, not by case ID (which also encodes position and pass).

For target *t* with technically eligible presentations *P(t)* (six with complete data):

- **Average estimated gaze** (circle in Figure 1) = (1/|P(t)|) Σ centroidₚ, where centroidₚ is the analyzer's mean
  smoothed position of presentation *p*'s valid measurement samples. Each presentation counts equally (one sixth with
  complete data), however many samples it has; samples are never pooled directly.
- **Average target error** (bar in Figure 2) = (1/|P(t)|) Σ errorₚ, where errorₚ is the analyzer's presentation mean
  error, the mean over *p*'s valid samples of `sqrt((smoothed_x − target_x)² + (smoothed_y − target_y)²)`.

The bar is **not** the distance from the target to the averaged position: errors in opposite directions cancel in that
average but not in the bar. Both values are listed in `target_summary.csv` (`mean_presentation_error_norm` and
`centroid_displacement_norm`), with the contribution count, the contributing and missing presentations, and the
smallest and largest presentation error per target.

**Reading Figure 1.** The phone screen drawn to scale in screen coordinates: origin top left, x to the right, y
downward. Targets are labelled A1–A4 (top row, left to right) to D1–D4 (bottom row). Blue crosses are the 16 target
positions, orange circles the average estimated gaze, arrows go from target to average, and the small orange label
names the circle's target. Estimates are the pipeline's smoothed output, clamped by the model to the screen, so a
circle can sit on an edge but never beyond it. An average hides the spread of samples and of the six presentations.

**Reading Figure 2.** One bar per target, A1 … D4; lower is better; the value is printed above each bar. The dashed
0.10 line is the error condition of the original per-presentation success rule, shown for reference only: success was
judged per presentation and also needed coverage ≥ 0.80, at least 10 valid samples and a complete presentation, so a
bar below the line would not show that every presentation passed. The y axis runs from 0 to 0.5 and grows in steps of
0.05 only when a bar needs more room; it is shared by every session drawn in one run.

**What this view is not.** It is descriptive. It computes no pooled acceptance metric, threshold or verdict, and it
can hide differences between head positions: in the exploratory recording LOWER had the largest errors; in the final
one NEUTRAL and HIGHER had opposite vertical offsets, so the averaged circles fall between them. The per-block metrics,
verdicts and presentation tables remain in `../data/derived-final/` (final), `../data/derived/` (exploratory) and
section 3.3 of the main report; the figures' captions repeat the per-block verdicts unchanged.

**Units.** x is divided by the display width and y by the display height. The error is not a percentage of the screen
diagonal. On the 1080 × 2316 px display a purely horizontal error of 0.10 is 108 px and a purely vertical one 231.6 px.

**Missing data.** The analyzer's technical eligibility is used unchanged (complete presentation, ≥ 10 valid measurement
samples, coverage ≥ 0.5). With fewer than six eligible presentations, the target is marked partial: a hollow circle
labelled with the count (for example `A1 (4/6)`) and a light hatched bar with the count above it; the average uses only
the eligible presentations. With none, the cross keeps its label `(no estimate)` and the bar shows `N/A`. A missing
value is never drawn as zero, and the caption names the presentations that were not eligible, grouping targets that
share them. In the exploratory recording all 96 presentations are eligible (6 of 6 per target). In the final recording
no LOWER presentation has a valid sample, so every target is partial (4 of 6: NEUTRAL and HIGHER, both passes).

## Regenerating

From the repository root, with matplotlib 3.11.2 and numpy 2.5.4
([`../tools/requirements-plot.txt`](../tools/requirements-plot.txt)):

```powershell
# Final collection
python -B docs\calibration-comparison\tools\calib_eval_figures.py --summary docs\calibration-comparison\data\derived-final\summary.json --selection docs\calibration-comparison\data\analysis-inputs-final.json --figures docs\calibration-comparison\figures\final
# Exploratory collection (draft): write into a scratch folder and compare; figures\draft is kept as generated
python -B docs\calibration-comparison\tools\calib_eval_figures.py --summary docs\calibration-comparison\data\derived\summary.json --selection docs\calibration-comparison\data\analysis-inputs.json --figures <scratch folder>
```

The output is deterministic for the same inputs and library versions; rerunning on the same inputs leaves the session
folder byte-identical. The final figures were drawn with `calib_eval_figures.py` 1.1.1, the draft ones with 1.1.0. 1.1.1
changes only sessions with partial data or a block without valid samples (the caption names the presentations left out
and the positions without samples, and a figure grows at the bottom instead of clipping a long caption), so the draft
figures and table regenerate byte-identically; only the tool version recorded in the manifest differs.

The tool refuses a `summary.json` that was not produced from the current selection manifest,
incomplete sessions, sessions with integrity problems or unverified checksums, and a mix of technical-pilot and other
sessions; a pilot figure set states "Technical pilot" on every figure. The per-position view is still available with
`--view per-block --derived <dir>`; see the archive README.
